# Plan 流程重构 V12

Worker 版本：`2026-11-01-transport-pending-12`。前端步骤协议：`planWorkflowContract: 2`；地点候选协议继续使用 `3`。

## 部署

1. 将 `worker/travel-companion.mjs` 的**完整内容**复制到原 Cloudflare Worker，整体替换并部署。此文件已打包，不需要上传 assets 或设置新密钥。
2. 保留原有 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`、`AMAP_WEB_KEY`、来源白名单及可选访问码。
3. `/api/health` 应显示版本 `2026-11-01-transport-pending-12`、`planWorkflowContract: 2`、`planReviewEndpoint: true` 和 `internationalCandidates: true`。
4. 前端需要同时更新 `index.html` 和 `assets/plan-core.js`、`assets/plan-workflow.js`、`assets/plan-workflow.css`，不能只替换 index。刷新后应看到 `PLAN TOGETHER · V12`。
5. 已保存的首版方案、兴趣、历史版本和候选会继续读取；旧的待加入候选会迁移到对应城市的第一天，可在逐天选择中调整。

## 新的完整流程

- 全程总览：保留地理坐标地图、城市与每天的简短安排、餐饮住宿建议；可修改旅行需求。
- 逐天选择：每次只展示一天，支持切日、时间段、地点移除与撤销、加入当天、同城备选每次三个与换方向。选择在当前设备保存；选择不逐次请求 AI。
- 综合评估：用户明确提交后请求 `task: review`。AI 检查节奏、地理衔接和取舍，返回可以直接点的具体 A/B；前后台共同校验每个调整对应已选地点。没有实质问题不制造问答。详细检查默认折叠。
- 交通与订票：为每条跨城段给具体交通建议，允许更换方式；门票、预约、酒店和交通衔接整理为准备清单。勾选仅表示已记下，不代表已预订，也不要求订完才能完成行程。
- 最终行程：确认后直接生成最终逐日安排；地图位置仅复用已有可信匹配，未匹配的地点保留为待匹配，不等待地图接口。校验城市、天数、每天地点、选定时间段与交通选择，校验失败不覆盖旧方案。生成后进入工作台不再调用 AI。
- 返回每天修改时，已同意的 AI 增减会转换为每天的真实选择，不会因返回而悄悄恢复被移除地点；有新选择需要重新评估。
- 自由输入、攻略截图/文档、详细讨论与历史版本集中在更多定制。原有资料提取器保留。

## 源码结构与构建

- `assets/plan-core.js`：纯状态、逐日修改、版本恢复、评估操作及最终方案约束。前端和 Worker 共用同一份规则。
- `assets/plan-workflow.js`：步骤视图、会话保存和迁移、AI 工作状态及显式任务调度。旧的 Plan 讨论框和逐日长列表控制器已移除。
- `assets/plan-workflow.css`：步骤、单日卡片、决策和准备清单样式。
- `index.html`：保留首版需求界面、API、资料读取、地图、候选身份校验及其余功能。
- `worker/service.mjs`：Worker 服务源文件。
- `scripts/build-worker.mjs`：将共享规则和服务源文件打包为可整体复制部署的 `worker/travel-companion.mjs`。

修改共享规则或 Worker 源文件后执行：

```sh
node scripts/build-worker.mjs
node --test tests/*.test.mjs
```

## 验证范围和边界

自动检查覆盖地点身份、兴趣筛选、海外候选、地图歧义、单日选择不串日、恢复进度、明确 A/B、同城跨日调整、交通完整性、失败后恢复及最终方案原子提交。浏览器使用明确标注的模拟数据走完逐天添加、切日、重新打开、A/B取舍、交通选择、清单、最终方案与进入工作台。模拟夹具不发布。

真实 DS/高德效果仍需部署后盲测。海外候选支持 AI 知识推荐及加入行程，但海外位置解析尚未接入，明确不提供假坐标。国内地图匹配不代表营业/预约/门票核验。交通为建议，未接入真实道路耗时、车次库存、付款或代订服务。页面显示的等待秒数是真实等待时间，不模拟完成百分比。


## V12 交通缺项不再阻塞

综合评估保留有效的景点 A/B 建议。交通推荐缺少路段、选项或推荐 ID 时，按实际路线生成明确的待定项，不丢整份评估，不随意选第一个方式。第四步每段都可选择“待定”；最终行程和准备清单保留对应路段及出发前补齐提醒。`pendingTransportSupported: true` 表示支持此逻辑。

旧 Worker 因交通或 A/B 字段不完整拒绝评估，或其他评估请求失败时，新前端提供“先沿用当前安排，继续下一步”。此路径明确显示综合评估尚未完成，暂时沿用当前景点，不声称 AI 检查已通过。地点身份与用户明确增减的校验仍保留。


## V12 定位不再阻塞

地点匹配不再是最终生成的前置条件。系统复用已有可信坐标，其余明确标为“地图待匹配”，保留用户选定的具体名称和日期，不伪造坐标，不要求用户手工定位。查看每日地图时可继续由地图服务匹配；临时失败不妨碍全程行程。

最终方案仍严格校验城市、天数、每一天的地点和用户时间段；已确认地点通过原候选 ID 或原名称保持身份，不为补地图而私自换点。Worker 的 `nonBlockingMapResolution: true` 表示支持此逻辑。
